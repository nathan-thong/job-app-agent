# Cover Letter paragraphs carry Profile Evidence provenance

Each model-generated Cover Letter Paragraph contains its prose, the Requirements it addresses, and the Profile Evidence used to write it. The backend verifies Requirements against the Gap Analysis set and restricts provenance to checked evidence already present in a Match or Adjacent assessment for one of those Requirements. The UI renders only prose, while Critique receives the sanitized paragraph and provenance. A plain list of strings would force Critique to reconstruct grounding from scratch, and allowing arbitrary Profile citations would let Draft bypass Gap Analysis. Hidden provenance does not prove every phrase is supported, but it creates an auditable path and makes unsupported claims easier to detect.

## Consequences

The Draft response is structured for integrity rather than mirroring the final plain-text presentation. It includes required, no-default `dropped_evidence_count` and `dropped_requirement_count`; the agent removes unknown or Gap Requirements and unverifiable or unapproved evidence, increments the matching counter, and preserves prose for Critique to judge. Copying and display omit provenance and counters. A paragraph may omit Requirements and evidence only when it makes no candidate-specific factual claim; factual prose without verified provenance produces a blocking Critique Finding. Users may edit only after the automatic loop finishes. Once edited, the UI must state that the previous verdict and provenance apply to the generated version rather than the modified text, and it must not spend another Critique call automatically. Pipeline state preserves the generated letter immutably and stores edits separately, allowing a no-cost reset to the generated version; Copy follows the visible version.
