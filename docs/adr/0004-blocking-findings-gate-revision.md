# Only blocking Critique Findings require revision

Critique returns `pass` or `revise` plus Findings. Each Finding has an enum-constrained code, severity derived from that code, an optional one-based paragraph number, and a specific message; letter-wide Findings omit the paragraph number. Blocking codes are `unsupported_claim`, `adjacent_as_match`, `missing_role_specificity`, `forbidden_structure`, and `incoherent_prose`. Advisory codes are `word_count`, `repetition`, `weak_phrasing`, `generic_tone`, and `missed_opportunity`. The loop revises when any blocking Finding exists and may pass with advisory Findings, avoiding extra model calls in pursuit of subjective perfection while never accepting an integrity failure.

## Consequences

The model returns semantic Findings only. `CritiqueResponse` contains Findings and the derived verdict without normalization counters. Draft hard-validates paragraph and evidence shape but does not reject forbidden prose. The backend Critique deterministically adds word-count and forbidden-structure Findings and still performs the semantic call, so one revision receives the complete problem set rather than discovering failures serially. If that call fails, the stage errors and awaits explicit Retry; deterministic Findings alone can never produce `pass`. It normalizes out-of-range paragraph numbers to letter-wide, collapses duplicates by code and paragraph, and logs those corrections safely. It then derives each severity from its code and derives the verdict from the resulting set, so a model cannot return `pass` alongside a blocking Finding. On `revise`, Draft receives the previous structured letter, all trusted inputs, and every Finding ordered blocking first; blocking Findings are mandatory while advisory improvements must not weaken grounding. Each revision returns a complete replacement letter rather than paragraph patches, and all validation, provenance, and Critique checks run again. The final UI may show advisory Findings without treating the Cover Letter as failed. The frontend permits two revisions after the initial Draft, capping a run at three Draft and three Critique calls. If blocking Findings remain after the last allowed Critique, the pipeline returns the latest letter in a distinct `capped` state with those Findings visible; it does not mislabel the result as passed or make another call.
