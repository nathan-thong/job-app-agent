# Gap Analysis distinguishes Matches, Adjacent evidence, and Gaps

Gap Analysis produces one Requirement Assessment per Requirement with exactly one outcome: `match` when Profile Evidence directly supports it, `adjacent` when credible transferable evidence exists but does not satisfy it, or `gap` when no useful evidence exists. A binary matched/unmatched result would either discard useful adjacent evidence or tempt Draft to present transferability as direct experience; the third outcome preserves that evidence without laundering it into a Match. Each assessment embeds its complete Requirement, and the agent verifies one-to-one correspondence with the Extraction input, avoiding positional coupling or generated IDs. Match and Adjacent assessments carry Profile wording verbatim with a stable source section (`summary`, `skills`, `experience`, `projects`, or `education`) so the agent can check it without exposing brittle array indexes, while the model's interpretive reason stays separate.

## Consequences

Draft may emphasize Profile Evidence from an Adjacent assessment but must not claim the Requirement is met. Match and Adjacent require at least one checked evidence item, Gap requires exactly zero, and every outcome requires a short reason. Evidence not found in its named Profile section is dropped and counted. The original outcome and reason remain when at least one checked item survives; when none survives for Match or Adjacent, the agent deterministically downgrades the assessment to Gap, substitutes a derived reason, and logs privacy-safe rejection metadata instead of spending another model call.

The agent also normalizes model coverage into exactly one assessment per input Requirement, in original order. It keeps the first valid duplicate, drops unknown and later duplicate assessments, and synthesizes a Gap with reason “No assessment returned” for each omission. `GapAnalysisResponse` requires `dropped_evidence_count`, `dropped_assessment_count`, and `synthesized_assessment_count` with no defaults, proving both normalization passes ran; unknown and duplicate removals share the assessment counter while safe logs preserve their reasons. These corrections require no repair call, so Draft never silently loses a Requirement. Default logs contain reasons, counts, request IDs, and content hashes rather than Profile or rejected evidence text; explicit local content logging is opt-in and defaults off.

Tests and UI copy must avoid calling Adjacent a partial or weak Match. A fluent reason never substitutes for checked Profile Evidence.
